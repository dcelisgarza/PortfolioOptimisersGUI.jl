# PortfolioOptimisersGUI.jl — v1 Plan

Decisions below were settled in a grilling session on 2026-07-07. Terminology per [CONTEXT.md](CONTEXT.md); load-bearing choices recorded as ADRs in [docs/adr/](docs/adr/).

## Product definition

- **What**: an interactive **workbench** — load returns data, compose a Strategy (prior + optimiser + risk measures + constraints), run, inspect, tweak, re-run, compare.
- **Who**: Julia-literate quants. The UI speaks the library's own vocabulary and exports runnable Julia code; no dumbed-down parallel vocabulary.
- **Form**: local web app. `serve()` (optionally `serve(rd::ReturnsResult)`) opens the browser UI backed by the user's own Julia session.
- **Where**: this separate repo/package, depending on PortfolioOptimisers. The library never gains GUI dependencies or GUI-shaped metadata.

## Architecture

- **Stack**: Genie/Stipple + StippleUI; plots via StipplePlotly (existing `plot_*` recipes through the `plotlyjs()` backend) and StippleMakie/WGLMakie (future Makie extension). [ADR-0001]
- **Spec-centred**: forms edit a declarative Strategy Spec; one IR drives run / persist(JSON) / Code Export. [ADR-0002]
- **Hybrid UI generation**: curated shell screens per pipeline stage; estimator pickers + parameter forms auto-generated by reflection, overlaid by the GUI-side Schema Registry; `@argcheck` errors as universal fallback validation. [ADR-0004]
- **Execution**: async background tasks (Runner) with per-Run status and sweep progress; stop between sweep points only; no hard cancel in v1.
- **Solvers**: detect-only Backend Detection + full Solver editor. [ADR-0003]

## Session model

Workspace (1 dataset + Asset Sets) → N Strategies → N Runs each, kept for comparison. A frontier sweep is a structured family of Runs. Datasets stored by reference (path + ingest options); Runs cache outputs but are always recomputable from Spec + data.

## v1 scope

Stage tabs mirroring the pipeline:

1. **Data** — CSV/Parquet import with column mapping (dates, assets, factors, benchmark) → `prices_to_returns`; REPL handoff.
2. **Explore** — Phylogeny: dendrograms, networks, centrality over the loaded universe.
3. **Strategies** — master-detail editor: prior, optimiser, risk measures, constraints builder (Asset Sets, WeightBounds, linear constraint equations, budget).
4. **Runs & Compare** — weights, composition, risk contribution, cumulative returns, drawdowns, histograms; efficient-frontier sweeps with per-point weight inspection.
5. **Allocation** — Finite Allocation (Discrete/Greedy) on any Run's weights.

### Explicit v1 non-goals

No curated workflows for: Black-Litterman / Entropy Pooling view editors; Cross-Validation & hyperparameter search; meta-optimisers (NCO, Stacking, SubsetResampling); Uncertainty Sets. Also out: YFinance downloader, bundled demo datasets, worker-process runner. Some remain reachable through uncurated generic forms.

## Milestones

- **M0 — scaffold** (this commit): repo, CONTEXT.md, ADRs, plan, module stub.
- **M1 — de-risking spike**: one Stipple page with a Plotly recipe, a WGLMakie figure, one reflective nested form, one MeanRisk run end-to-end. Go/no-go on StippleMakie (fallback: static SVG/PNG for Makie figures).
- **M2 — engine**: Strategy Spec ↔ constructors ↔ Julia script; reflection Schemas + Schema Registry; round-trip tests.
- **M3 — spine**: Data tab (import + handoff) → Strategy editor → Runner → results plots. Single strategy, minimal constraints.
- **M4 — constraints + allocation**: Asset Sets, WeightBounds, linear equations, budget; Allocation tab.
- **M5 — explore + sweeps**: Phylogeny tab; frontier sweeps and run comparison.
- **M6 — polish**: Workspace persistence UX, Code Export polish, empty states, docs.
